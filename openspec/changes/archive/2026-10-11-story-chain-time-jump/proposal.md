# 提案：剧情链时光跳跃（让 1851-1912 的历史内容真正可达）

> 交付日期 2026-10-11，已上线并通过 e2e 全量回归。本提案为**实现后补记**：
> 决策依据、被排除的替代方案与验证数据都记录在此，供后续回溯与二次调整。

## 为什么 / Why

**游戏的核心时间承诺兑现不了。** 实测证据（`game-web/tests/unit/balance-regression.test.ts`，200 局通关模拟）：

| 指标 | 实测 |
|---|---|
| 通关回合数 | 均值 35.5，中位 35，区间 [25, 51] |
| 每回合推进 | 1 个月（`useTurn.endTurn`） |
| 一局实际走到的年份 | **1853-11（中位）～ 1855-03（最慢）** |

而 14 条剧情链的历史锚点是 1851 / 1853 / 1856 / 1861 / 1862 / 1865 / 1871 / 1883 / 1894 / 1898 / 1899 / 1901 / 1904 / 1911——**12 条永不触发**，玩家一局只能看到 2 条。目标栏固定文案「成就霸业（1851-1912）」（`docs/game-design.md`）因此是虚假承诺，`time_up`（年份 > 1912）结局更是死代码。

第二个缺陷是触发判定本身：`matchTimeWindow` 要求 `startYear === 当前年`，日历一旦跨过那一年，该链**永久错过**，哪怕玩家真的玩到了 1861 年也会因为"不是正好 1861"而看不到洋务运动。

## 改什么 / What Changes

- **服务端**：`matchTimeWindow` → `matchNextChain`，取 `startYear` **不早于**当前年份的最早一条链。
- **服务端**：链锚点晚于当前日历时，事件携带 `eventDate: { year, month }`（锚点年 1 月），并把描述改写为
  `【当前年—锚点年 年间】+ 链概述 + 节点描述`，交代这段空档是怎么过去的。
- **前端**：`useTurn.startTurn` 拿到事件后，若 `eventDate` 晚于当前日历则推进日历（不回拨）。
- **文档**：`docs/API.md`（新增流式与时光跳跃两节）、`docs/game-design.md`（回合机制与值域说明）。

## 关键决策与被排除的方案

| 决策 | 理由 |
|---|---|
| 只在**链首**（`time-window` 路径）判定跳跃 | 链内后续节点走 `pending-chain` 接续，日历应停在链开始年代；否则一条 5 节点链会把时间往前推 5 次 |
| 跳跃目标恒为锚点年 **1 月** | 锚点只精确到年；给月份编造语义会误导玩家 |
| 过场文案用**模板**而非 LLM 生成 | 零 token 成本、零延迟、无失败面；且它只是叙事胶水，不需要创造性 |
| 排除「1 回合 = 1 年」 | 改一行即可，但金田起义→定都天京→天京事变会挤在相邻三回合，历史节奏失真 |
| 排除「分段加速（里程碑控速）」 | 节奏最好，但要重调每回合产出与事件频率并重跑平衡基线，工作量与风险都数倍 |
| 排除「多幕结构」 | 最忠实历史，但是全新玩法结构 |
| `startYear >= year` 而非 `===` | 这是时光跳跃成立的**前提**：跳跃目标就是下一条链的锚点，严格相等会让链被永久跳过 |

**已知副作用（接受）**：前置链未完成时，`>=` 会取更晚的无前置链，导致历史顺序前跳（如 1894 甲午被跳过而触发 1898 戊戌）。被跳过的链因年份已过去而永久不再触发。这与改造前"错过即丢失"同构，且触发条件苛刻（剧情链一旦开始就会线性走完），故接受。

## 影响 / Impact

| 影响面 | 改动 |
|---|---|
| 后端 `server` | `generate-event.ts`（`matchNextChain` / `buildChainEvent` 增参 / `eventSchema` 增字段） |
| 前端 `game-web` | `useTurn.startTurn` 应用 `eventDate`；`GenerateEventResponse` 与 `GameEvent` 类型同步 |
| API | `POST /api/game/generate-event` 响应新增可选 `event.eventDate`（向后兼容，老客户端忽略即可） |
| 数据库 | 无变更 |
| 文档 | `docs/API.md`、`docs/game-design.md` 已同步 |
| 测试 | 服务端 API 用例 +3（跳跃下发 / 链首限定 / 前置未满足改取后一条）；前端 +3（应用跳跃 / 不回拨 / 无 eventDate 不变） |

## 能力 / Capabilities

### Modified Capabilities
- `story-chain-engine` - 剧情链触发由「年份严格相等」改为「取下一条不早于当前年的链」，并新增按锚点推进游戏日历的时光跳跃
