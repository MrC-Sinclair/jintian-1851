# 提案：让平衡模拟底盘看得见剧情链（可选开关 + 镜像守卫 + 新基线）

## 为什么 / Why

`tests/sim/balance-sim.ts` 是整个项目唯一的平衡回归依据（C1 跨提案校验、养饷标定、外交不变量都靠它），
但它此前**完全不跑剧情链**：文件头写着「仍未建模：剧情链触发与时光跳跃」。
于是底盘量到的 86.0% 胜率，量的是一款「14 条历史剧本全部不存在」的游戏 —— 而真实游戏里
链节点优先于 LLM 下发、且每次下发都是大额度固定增益。这个缺口不只是「少了一条线」，
它让三类结论无法回答：

| 问题 | 不建模链能否回答 |
|---|---|
| 剧情链给多少属性？会不会提前撞线？ | 不能（链根本不在场） |
| 1851—1912 的年份跨度真的走得到吗（`time_up` 结局）？ | 不能：200 局最晚只到 1855 年，日历只走月不走年 |
| 链完成度能不能参与结局判定（#4 的前置）？ | 不能：底盘里没有 `chainsCompleted` 这个量 |

另有一个更隐蔽的问题：底盘刻意**不 import** 服务端的 `STORY_CHAINS`（设计意图是
「自包含存放，使回归基线不随服务端内容漂移」）。自包含的代价是镜像会烂掉——
服务端改一个节点的 effects，模拟会悄悄量出一个不再对应真实游戏的基线，且没有任何信号。

## 改什么 / What Changes

全部改动都在 `game-web/tests/` 内，**不改任何生产代码、不改服务端、不改数值**。

- **`useStoryChains` 开关（默认 `false`）**：打开后按真实优先级下发链节点
  （挂起节点 → 下一条可触发链 → 兜底事件），时光跳跃把日历前推到锚点年，
  并复刻 `matchNextChain` 的「允许未来锚点」这条规则（它是时光跳跃的前提，不是 bug）。
- **回合顺序与 `useTurn` 对齐**：破产（产出前）→ 净产出 → 断粮/兵溃（产出后）。
  资源惩罚**不做成开关**，理由见下表。
- **`SimOutcome` 新增 `chainsCompleted` / `finalYear`，`SimReport` 新增 `avgChainsCompleted` / `maxFinalYear`**
  —— 链完成度与年份跨度第一次成为可测量。
- **镜像漂移守卫**：新增 `tests/unit/sim-chain-mirror.test.ts`，把 `SIM_CHAINS` 与服务端
  `STORY_CHAINS` 逐链（chainId / startYear / 节点数 / 前置链）、逐节点逐选项（effects 深比对）对账。
- **基线快照**：`balance-regression.test.ts` 文件头记录开链/关链两组数字 + 一条新的对比用例。

## 关键决策与被排除的方案

| 决策 | 理由 |
|---|---|
| 链做成**默认关闭的开关**，而不是直接打开 | 直接打开会让既有 86.0% 基线失去参照物（它已被 4 处断言引用）。开关关掉后 200 局的逐资源下限、中位数、range 与改动前**逐字节相同**，实测确认：86.0% / 37.5 / median 37 / [23,51] / 银两0·兵员15·粮草160·名望0 |
| 镜像表**不改成直接 import 服务端** | 那会把「服务端改一个数值 → 200 局基线静默漂移」重新变成现实，正是本文件设计意图要防的。改为「镜像 + 深比对守卫」：漂移仍然会发生，但变成**测试红**，逼人有意识重标定 |
| 资源惩罚**不**再加一个开关 | 惩罚自 #3 起已无条件纳入，86.0% 这条基线**本身就是含惩罚测出来的**。再加一个「关惩罚」档位等于给一条没人跑的分支做维护，且会让人误以为存在「旧基线可复现」的第二组数字 |
| 用真实 effects 拼接镜像，不用占位数值 | 中途我用过手写的近似 effects，量出「开链 0% 胜率」——那测的是我自己编的数据。换回服务端真值后结果翻成 100%/22 回合，方向完全相反。**近似值在本底盘里比缺值更危险** |
| 断言只锁「开链 ≥ 关链」这类关系，**不**锁 22 回合这个数 | 22 回合定局是当前数值下的**病症**，不是希望长期成立的性质。数值由文件头快照如实记录，产品侧收紧链密度后该断言不必跟着改，快照则需重标定 |

## 实测结论（200 局/组，确定性可复现）

> ⚠️ **本表是 14 条链时的标定，已被后续 `story-chain-anchors-and-completion` 取代**
> （链补到 23 条后开链组重标定为 100.0% / 22.0 / 链完成 **5.00** / 1865，
> 开链+NPC 组变为 98.5% / 46.0 / 13.79 / 1892；关链基线 86.0% 始终逐位不变）。
> 保留原数字是为了留证据链，不要拿它当现行基线。

| 组 | winRate | avgTurns | 链完成均值 | 最晚年份 | 逐资源下限 |
|---|---|---|---|---|---|
| 关链（既有基线） | 86.0% | 37.5 | 0 | 1855 | 银两0/兵员15/粮草160/名望0 |
| 开链 | **100.0%** | **22.0**（range=[22,22]） | 6.00 | 1865 | 银两668/兵员115/粮草800/名望19 |
| 开链 + simple NPC | 100.0% | 42.6 | 13.47 | 1911 | 银两446/兵员15/粮草750/名望19 |
| 关链 + simple NPC | 7.0% | 47.4 | 0 | 1855 | 同上 |

⚠️ **最重要的发现（不由本提案修复，交给 #4）**：开链后 200 局**全部恰好在第 22 回合必胜，方差为 0**，
22 回合只走到 1865 年（14 条链完成 6 条）就撞线，「复兴六十年」的跨度根本没走满。
根因不在模拟：链命中时不调 LLM 因而**挤占普通事件**，而 `matchNextChain` 允许未来锚点导致链首接链尾连发，
节点 effects 量级（±8~12）远大于兜底事件（±3~7），bot 又恒定选最强项。
两条 NPC 压力路径（7% vs 100%）说明难度主要由 NPC 供给，链一开就把压力抵消光了。

## 影响 / Impact

| 影响面 | 改动 |
|---|---|
| 生产代码 | **无**（`game-web/src` 与服务端均未改动） |
| 模拟底盘 | `tests/sim/balance-sim.ts`：`SimOptions.useStoryChains`、链匹配/构造/记账、`SIM_CHAINS` 镜像表（14 链 42 节点）、`SimOutcome`/`SimReport` 新字段、文件头声明改写 |
| 测试 | 新增 `tests/unit/sim-chain-mirror.test.ts`（3 用例）；`balance-regression.test.ts` 新增 1 用例 + 文件头快照；`game-web` 单测 29 文件 **461 全绿**，lint/typecheck 通过 |
| 基线 | 既有 86.0% 基线**逐位不变**（开关默认关）；新增开链基线 100% / 22 回合，仅供记录与对比 |
| 文档 | 本提案 + `openspec/changes/resource-pressure-and-bankruptcy/specs/turn-engine/spec.md` 里「保留未建模剧情链的显式声明」那句同步更正 |

## 能力 / Capabilities

### Modified Capabilities
- `turn-engine` - 「通关模拟底盘与真实回合循环对齐」从「不建模剧情链」升级为
  「可选建模剧情链与时光跳跃，默认关闭以保持基线可复现，并由镜像守卫防数值漂移」
  （delta 见 `specs/turn-engine/spec.md`）
