# 任务：资源压力（养饷 + 财政破产）

> 验证命令与结果如实记录，未执行的项标注为未做而非打勾。

## 1. 标定（先测再改，不改源码）

用临时探针 mock `calcTurnYield` 注入消耗/惩罚，跑 200 局/格；探针跑完即删。

- [x] 现状实测：银两归零占 **5.1%** 回合、粮尽 **0.0%**、兵溃 **0.0%** → 三条惩罚线里两条从未触发
- [x] 原方案 (c)「提高粮草/兵员消耗」实测：粮草 −15→80.5%、−25→15.5%、−40→0%；
      且 **兵员 −10/回合 与不扣的结局分布完全相同**（+15 产出把它整个吃掉）→ (c) 是悬崖、兵员直扣无效
- [x] 原方案 (a)「正向补给」实测：粮草 +15/回合 胜率 95.5% → 95.5%，**对平衡零影响**
- [x] 原方案 (b)「破产后果」实测：轻档 87.0%、中档 82.0%、后果+额外消耗 59.0%
- [x] 用户选定：(a) + (b) 轻档 + 兵员改「养饷联动」
- [x] 养饷 × 破产 联合标定（第一版，惩罚在产出前判）：K=2→90.0%、K=4→86.0%、K=6→55.5%
- [x] **发现第一版标定的时点错误**：真实 `resource-penalty` 在产出之后判，
      而净产出恒为正 → 破产永远不触发。用真实代码路径复测 K 得到阶跃：
      K=4→95.5%（形同不存在）、K=6→59.0%、K=8→19.5%、K=10→6.0%
- [x] 据此把破产判定拆成独立函数并**刻意放在产出之前**，再用真实代码路径复测：
      K=2/3→90.0%、**K=4→86.0%**、K=5→69.5%、K=6→59.0%、K=8→19.5% → 梯度恢复，定 K=4
