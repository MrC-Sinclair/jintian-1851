# 五维属性封顶与胜利阈值重标定补记

## Why

`applyEffects` 对五维属性**只加不夹**，实测军事涨到 129，直接违反 `game-design.md:32`
写明的「每维取值范围 0-100」：进度条溢出，且**单维堆叠**就能把加权平均抬过胜利线。
落地在 `c8f5850`，此前没有对应提案，本 change 是补记。

更关键的是它牵出胜利阈值的真实标定问题：封顶后若阈值仍取 90，200 局模拟里最优策略
bot 的胜率从 99.5% 塌到 48.5%，而 `avgPower` 只有 88.2 —— 说明大量对局卡在 89 附近
撞回合上限。也就是说**封顶之前的"几乎必胜"是这个越界 bug 撑起来的**，不是平衡设计的结果。

## What Changes

- `applyEffects` 给五维加上限 `Math.min(ATTRIBUTE_MAX = 100, …)`。
- **刻意只夹上限**：下限留负，崩溃判定依赖 `≤ 0`，由 `game-store.test.ts` 的断言锁住。
- 与之配套把 `VICTORY_THRESHOLD` 从 90 重新标定到 85（不是"降低难度"，是修正量纲）。
- 清掉 8 处硬编码的 90（帮助页、开局引导、GoalPanel 文案、FocusPanel 刻度标签、
  即将胜利的建议文案等），并把 FocusPanel 进度条刻度从 CSS 写死的 `left: 90%`
  改为绑定常量 —— 阈值一改，这些位置本来会集体说谎。

## Impact

| 层级 | 影响 |
|---|---|
| 前端 | `stores/game.ts` 属性夹上限；`utils/constants.ts` 阈值 85 与 `ATTRIBUTE_MAX`；GoalPanel / FocusPanel / 帮助与引导文案改取常量 |
| 后端 | 无（综合实力由前端算） |
| 测试 | `game-store.test.ts` 锁住「夹上限不夹下限」；`balance-regression` 基线换为新数字 |
| 文档 | `docs/game-design.md` 阈值与「加权平均」口径同步（本轮另见清残留 90 的提交） |

## 被排除的方案

- **上下限一起夹（0-100）**：会让 `military ≤ 0` 之类的崩溃结局永不触发，直接改写结局
  判定语义；现方案保留负值作为崩溃依据，只封溢出。
- **不封顶、只把阈值提到 130 之类**：等于承认属性可以无界增长，UI 刻度与
  `game-design.md` 的 0-100 约定都会失真，是掩盖而非修正。
- **阈值保持 90 并接受胜率塌到 48.5%**：把 bug 修复的代价转嫁成难度突变，且与
  C1「winRate ≥ 0.9」不变量冲突。
- **只改文案不改常量绑定**：留着 8 处硬编码，下次调阈值仍会集体说谎。
