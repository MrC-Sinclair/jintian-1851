# 局势简报超时与前端非阻塞补记

## Why

两处静默故障都是线上实测出来的，落地在 `232dcf3`，此前没有提案，本 change 是补记。

1. **10 秒超时画在了延迟分布的中位数上**：线上连续 8 次调用 8/8 卡在 10.09s 超时，
   返回空简报却仍报 200 —— 玩家侧表现为"军师永远没话讲"，而监控上看不出任何失败。
   超时预算贴着中位数等于把一半请求判死。
2. **前端 `await` 了简报**：`startTurn` 里简报与事件生成虽然是并行发起，但整回合开始
   要等两者都回来才交还玩家，于是简报成了首屏延迟的额外下限（最坏情况叠加一次 LLM 往返）。

## What Changes

- 简报超时 10s → 20s（`BRIEFING_TIMEOUT_MS`，实测线上 10s 会 100% 命中超时）。
- 前端不再 `await` 简报：事件就绪即交还玩家，简报回来后异步落地。
- 加请求序号 `briefingSeq`：并发回合下慢返回的**旧回合**简报必须丢弃，不得覆盖新回合简报
  （不 await 之后必然出现的乱序问题，这是这条改动的硬前提）。
- 降级语义不变：失败仍返回 200 + `X-Fallback: true` 的空简报，不阻断游戏。

## Impact

| 层级 | 影响 |
|---|---|
| 后端 | `advisor-briefing.post.ts` 超时常量 10s → 20s |
| 前端 | `composables/useTurn.ts`：简报发起不 await、`briefingSeq` 丢弃迟到响应、失败降级为 null |
| 数据库 | 无 |
| 文档 | `docs/API.md` 已记 20s 与其理由（本节把它同时写进规格） |

## Capabilities

### New Capabilities

（无）

### Modified Capabilities

- `ai-advisor`：「新回合军师主动局势简报」改为不阻塞首屏并要求乱序保护；
  「局势简报 API 规格」补上超时预算与"超时不得伪装成成功"的口径。

## 被排除的方案

- **把简报改成按需拉取（玩家点开军师面板才要）**：省掉一半 AI 成本，但丢掉"无需提问就有
  局势分析"这一设计目标，属于产品取舍，不为超时问题而顺带改它。
- **只调超时、不解除 await**：首屏仍被一次 LLM 往返拖着，超时只是变得"不容易撞上"。
- **超时后重试一次**：简报是纯增益信息，重试等于再花一次调用成本换一条建议，
  且会把首屏不确定性地拉长到 40 秒；宁可降级为空。
- **用「返回 200 但字段为空」表示超时**：这正是修复前的做法，也是它能长期不被发现的原因；
  现在超时/失败一律带 `X-Fallback: true`，可被监控与成本报表区分。
