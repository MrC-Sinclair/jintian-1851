# 提案：兜底事件池扩容 60 → 90（每类 +6），并给「有权衡的选项」装上护栏

## 为什么 / Why

两个各自独立、又互相咬合的缺口：

1. **长局必然抽干池子。** 池子 60 条按 5 类均分，每类只有 12 条。降级路径此前已加避重
   （`getRandomFallbackEvent(type?, avoidTitles?)`），但**避重只能改变抽取顺序，改变不了总量**——
   一局 35~50 回合、每回合都要事件，LLM 频繁降级时长局仍会在同类里翻来覆去出同样的事。
2. **粮草/兵员两条惩罚没有触发面。** `resource-penalty` 规定 `food ≤ 0` 触发饥荒、`troops ≤ 0`
   触发溃散，但 200 局模拟实测这两条**触发回合占比均为 0.0%**（粮草最低 160、兵员最低 15），
   根因是内容侧几乎没有消耗/补给粮草与兵员的事件：全池 + 14 条剧情链里
   `food`/`troops` 出现 43 次**全是负向，正向补给 0 条**。
   #3 把破产后果接上银两之后，粮草/兵员这两条线仍悬空——只能靠内容补，数值掩盖不了。

另外旧池有个一直没被约束的问题：**26/60 条事件存在严格占优选项**
（某个选项在全部 effects 字段上 ≥ 另一选项且至少一项 >），玩家不必思考就能选对。

## 改什么 / What Changes

- `server/server/runtime/fallback-events.ts`：每类各 +6 条，共 60 → **90 条（5 × 18）**。
  文件头写明扩容的两条硬约束（同类主题不重复、≥1/3 新事件带粮草/兵员收支）。
- 新增 30 条事件（题目见 tasks.md 第 2 节），其中 **15 条带粮草或兵员收支（50%）**，
  含正向补给选项的有 **11 条**（如「屯田实边」拨荒田给勇丁 food+250、「捻军荡平」招抚降众给田
  food+100/troops+80、「蚕桑歉收」劝民改稻以济口粮 food+120），给休眠的断粮/兵溃惩罚创造触发面。
- `server/tests/unit/fallback-events.test.ts`：计数 60→90、各 12→各 18；
  **新增三条护栏**——标题全局唯一、扩容清单内无严格占优选项、新增事件 ≥1/3 带粮草/兵员收支。
- 文档同步：`docs/game-design.md`（池规模 + 扩容规则 + 每类 18 条的等量命中说明）、
  `docs/ai-cost.md`（降级表里的 60 条 → 90 条）、`generate-event.ts` 头注释。

## 关键决策与被排除的方案

| 决策 | 理由 |
|---|---|
| 「无严格占优选项」只对新登记的 30 条强制 | 旧池 26 条违规是既存事实，一并整改等于重写 26 条事件的数值，会直接冲击平衡基线且远超「扩容」的范围。改为**新增强制 + 存量登记在案**，测试注释里写明「不写进 `EXPANDED_TITLES` 就等于没测」 |
| 护栏用显式标题清单而不是「全池断言」 | 全池断言要么现在就有 26 条失败，要么得写成棘轮阈值（`≤26`）——阈值型断言失败时报不出「谁新增了违规」，标题清单失败直接指出事件名 |
| 粮草/兵员收支按「≥1/3 新事件」硬约束 | 这是 #3 遗留缺口的直接补丁。只加消耗不给补给会把游戏变成单向惩罚，所以清单里刻意含正向补给事件 |
| 历史剧情类新增 6 条选 1868/1874-81/1875/1877-78/1899 | 上方 12 条已覆盖 1851/1856/1861/1894/1898/1901/1904/1906/1911，中间 1865-1893 段是空白；与 #4 要补的剧情链锚点是同一批年代，先让兜底池有内容可降级 |
| 不动 `balance-sim` 的 `FALLBACK_POOL` | 模拟底盘用的是自己那份 30 条硬编码 mock 池，**不读服务端兜底池**。本轮不打通（打通属 #11 模拟底盘失真），但因此**平衡基线不会因本次扩容移动**，这点必须写清以免误读 |
| effects 量级沿用属性 ±3~15、资源 ±50~500 | 与既有测试的上下界断言一致；新增事件的资源项刻意全部 ≥50，避免再造出 `food: -20` 这类无感数字 |

## 影响 / Impact

| 影响面 | 改动 |
|---|---|
| 后端 `server` | `runtime/fallback-events.ts`（+30 条、文件头规则、历史注释里「池已扩充到 60 条」→ 90） |
| 前端 `game-web` | 无代码改动（`balance-sim` 的 mock 池独立，不读服务端池） |
| 数据库 / API | 无变更（`generate-event` 响应结构不变） |
| 平衡 | **基线不移动**（95.5%/86.0% 那套数字与本次无关，因为模拟底盘不消费这个池子）。真实游戏侧的影响要到 LLM 频繁降级时才显现 |
| 成本 | 无新增 LLM 调用；池子变大只影响降级路径的内容多样性 |
| 测试 | `fallback-events.test.ts` 12 → 15 例（计数改 90/18 + 新增唯一性、占优、粮草兵员覆盖三条） |
| 文档 | `docs/game-design.md`、`docs/ai-cost.md` 池规模同步 |
