# 提案：资源压力（养饷 + 财政破产），让「钱花光了」第一次有后果

## 为什么 / Why

`docs/game-design.md` 承诺银两「用于购械、赈灾、行贿」、粮草「断粮会触发饥荒」，实测两头都是空的：

| 事实 | 实测（200 局） |
|---|---|
| 银两归零有后果吗 | **没有**。5.1% 的回合停在 0，照常通关 |
| `economy_collapse` 结局出现过吗 | **200 局 0 次**——设计承诺的 7 种结局里有 2 种是死代码 |
| 断粮 / 兵溃惩罚触发过吗 | 粮尽 0.0%、兵溃 0.0% 回合，**两条惩罚从未触发**（粮草下限 180、兵员下限 15） |
| 养一支大军有成本吗 | **没有**。兵员只有「事件扣数」和「+15/回合 产出」两条线 |

三条资源线里，粮草和兵员之所以「有压力却测不出来」，根因是**内容侧几乎没有消耗它们的事件**
（food/troops 在 60 兜底事件 + 14 剧情链里出现 43 次全是负向、正向补给 0 条）。
但银两不同：它消耗得起（事件与外交都在花），缺的只是**花光之后的后果**。

## 改什么 / What Changes

- **养饷**：`TURN_YIELD` 的银两从「固定 +50」变成「+50 − 养饷」，
  `养饷 = ceil(兵员/100) × TROOP_UPKEEP_SILVER_PER_100`（K=4）。兵员 500 → 净 +30；兵员 1300 → 净 −2。
  `calcTurnYield()` 因此改为 `calcTurnYield(troops)`，两处调用点（`useTurn.endTurn`、`balance-sim`）同步。
- **财政破产**：新增 `calcBankruptcyPenalty()`，`silver ≤ 0` 时每回合 经济 −3 / 民心 −2，
  并在历史时间线记一条系统事件。**刻意在回合产出之前判定**（理由见下）。
- **模拟底盘补建模**：`balance-sim` 此前完全不跑资源枯竭惩罚，现在按真实时点跑
  （破产在产出前、断粮/兵溃在产出后）。
- **不变量改写**：`balance-regression` 的「开启外交不应降低胜率」被改写为「降幅 ≤15pt 且两条路径都 ≥0.8
  且外交确实被使用」；通关阈值断言 0.9 → 0.8。

## 关键决策与被排除的方案

| 决策 | 理由 |
|---|---|
| 破产判定放在**产出之前**（与断粮/兵溃时点相反） | 这是本轮最关键的一处。放产出之后的话，赋税是净正数入库，只要净产出 >0 就**永远触发不了**：实测 K=4 胜率仍是 95.5%（惩罚形同不存在），而要让 K 能咬人只能调到 6，那时净产出转负、银两常年归零，胜率一步跳到 59.0% —— 是阶跃不是梯度，没有安全调参空间。挪到产出之前后曲线变成 K=2/3→90.0%、K=4→86.0%、K=5→69.5%。语义上也站得住：月初空库=本月已靠加赋/赊欠度日，民心损伤既成事实，月底补税不能倒推抹掉 |
| 兵员压力做成**养饷联动**而不是直接扣兵员 | 实测直接扣兵员几乎无效：K=10 的兵员消耗被 +15/回合 产出整个吃掉，200 局的结局分布与不扣**完全相同**（c2 与 c3 两组数字一模一样）。要让兵员有意义只能让它花钱 |
| 不通过「下调 TURN_YIELD.troops」来制造压力 | 当初给 +15 就是为了修「兵员打光 → 兵溃每回合掉军事 → 永久下滑的死亡螺旋」。撤掉产出等于把这个已知 bug 请回来 |
| 破产惩罚取轻档（−3/−2）而不是中档（−6/−4） | 中档实测 74.5%，且 `economy_collapse` 会占 16/200 局 —— 难度一次跳两档，且没有中间实测点支撑 |
| 不做「正向补给事件」的数值调节 | 实测 (a) 方案（每回合粮草 +15）对胜率**完全无影响**（95.5% → 95.5%），因为粮尽本来就是 0%。它的价值在内容与体验（让粮草有意义、给 #5 事件池补正向一侧），**不能指望它做平衡调节** |
| 不做「提高粮草/兵员消耗」（原方案 c） | 粮草是唯一无产出的资源，所有压力会堆在一根线上形成悬崖：−15→80.5%、−25→15.5%、−40→0%。要安全做必须先有补给通道，属 #5 之后的事 |

**已知代价（接受）**：外交现在会**降低**胜率（with-diplo 86.0% vs no-diplo 95.5%，−9.5pt），
因为结盟/通商要花银两而银两终于有后果了。这是「外交从无成本增益变成财政权衡」的预期结果，
但它翻转了一条被锁住的跨提案不变量，需产品侧确认（见 tasks.md 第 5 节）。

## 影响 / Impact

| 影响面 | 改动 |
|---|---|
| 前端 `game-web` | `constants.ts`（`TROOP_UPKEEP_SILVER_PER_100`）、`turn-yield.ts`（签名 + `calcTroopUpkeep`）、`resource-penalty.ts`（拆出 `calcBankruptcyPenalty`）、`useTurn.ts`（3.45 破产 → 3.5 净产出 → 3.6 断粮兵溃）、`copywriting.ts`（系统事件文案不再写死数字） |
| 模拟底盘 | `tests/sim/balance-sim.ts` 纳入破产与断粮/兵溃惩罚，回合顺序与 `useTurn` 对齐 |
| 数据库 / API | 无变更 |
| 平衡 | 胜率 95.5% → **86.0%**（有意回收难度）；`economy_collapse` 首次可触发；`avgPower` 85.2 → 84.8，`avgTurns` 36.2 → 37.5 |
| 测试 | 改写 4 处断言（`turn-yield` 全部重写、`use-turn` 净产出 ×2 + 新增三档养饷用例、`resource-penalty` 新增破产 describe、`balance-regression` 阈值与外交不变量）；`game-web` 单测 457 全绿 |
| 文档 | `docs/game-design.md`：资源表银两行、养饷公式与 K 标定曲线、资源枯竭惩罚表（含时点不对称的理由） |
