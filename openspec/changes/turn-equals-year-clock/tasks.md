# 任务：时钟改为「1 回合 = 1 年」

> 2026-10-12 实施完成。验证命令与结果如实记录，未做的项标注为未做而非打勾。

## 0. 决策（已定并落地）

- [x] A = **A1**：`1 回合 = 1 年`
- [x] B = **B3+B2 混合**：1912 年结算；中途达标只锁定「中兴」评价、不结束游戏；
      `endedReason` 未新增枚举值（用「曾锁定 或 结算时达标」映射既有 `victory` / `time_up`）
- [x] C = **C1**：老档 `date`/`turn` 原样保留，之后每回合 +1 年（实测老档会收拢到次年 1 月，见用例）

## 1. 切时钟

- [x] `useTurn.endTurn` 第 4 步：`date.year + 1`、`month` 恒 1；函数头注释同步
- [x] `date.month` **保留不删**：6 处 zod schema、`eventDate` 结构、DB 已存 JSON 全部零变更
- [x] 3 处日期显示改为只显示年：`game-main`、`index`、`end-game`
      （月钟下"1851 年 1 月"是年号纪事，年钟后月份恒 1，显示出来会让人误以为日历按月走）
- [x] `useTurn.startTurn` 的时光跳跃判定保留（跨过锚点间空档年仍要用），注释改为年钟语义
- [x] `balance-sim` 第 7 步同步改年钟；`maxTurns` 默认 50 → **62**；文件头回合顺序重写
- [x] `balance-regression` 的 `BASELINE.maxTurns` 50 → 62（年钟下 50 回合只到 1901，
      一局都结算不了，胜率会直接归零 —— 这是改时钟的连带必改项）

## 2. 胜利规则改造（决策 B 的实现面）

- [x] `GameSave.zenithYear?: number` 新增（可选，旧档缺省即"从未锁定"）
- [x] `stores/game.ts` 新增 `lockZenith(year)`：已锁定则不覆盖，只写年份不结束
- [x] `useTurn.endTurn` 新增 3.8 步：实力首次达阈值 → 锁定当年 + 播一条「中兴已定」系统事件
      （放在破产/产出/断粮之后、turn+1 之前，读的是本回合全部效果落库后的最新属性）
- [x] `checkEndConditions`：崩溃优先级不变；`year > 1912` 时按
      「曾锁定 或 结算时 power ≥ 85」判 `victory`，否则 `time_up`；**1912 前一律 continue**
- [x] ⚠️ **`sync-save.ts` 的 `saveDataSchema` 是 strictObject** —— 不显式声明 `zenithYear`
      会把带该字段的存档**整条 400 拒掉**（不是忽略未知字段）。已加声明 + 2 条 API 用例守住
- [x] `time_up` 文案重写为"走完全程但未成中兴"；`victory` 文案加"历六十年而势不坠"；
      `isFailureEnd` 归类**保持不变**（time_up 仍算非失败），在文档里写明这是刻意的
- [x] 结局页新增「中兴已定 {zenithYear} 年」行（无该字段时整行不渲染）
- [x] `copywriting.SYSTEM_EVENT` 新增 `zenithLocked`；`turnYield` 措辞由「本月」改「本年」

## 3. Prompt 侧年份语义

- [x] 4 个 prompt（`generate-event` / `npc-actions` / `advisor-chat` / `resolve-decision`）
      的 `${year}年${month}月` 改为只报年，并在【当前时间】行加「1 回合 = 1 年」
      —— 报月份会让 LLM 按"一个月内发生的事"控制事件密度

## 4. 先测量（数值未动时跑的原始数据）

- [x] 年钟 + 未重标数值的四组实测（200 局/组）：
      关链 97.5% / 63.0 回合 / [63,63]；开链 100.0% / 44.0 / [44,44]；
      开链+NPC 73.5% / 44.0；关链+NPC 31.5% / 63.0
- [x] **验收标准达成**：`最晚年份 = 1913`（四组全部），`time_up` 第一次真的触发
      （关链 5 局、关链+NPC 136 局），不再是死代码
- [x] 名望合并分布实测（600 局）：p10=9 / p20=21 / 中位=54 / p75=65 / p90=77
- [x] 锁定年份实测：关链中位 1887（最早 1872）、开链 1882（200 局全部同年）、关链+NPC 1906
- [x] 链完成均值实测：**5.00 → 12.00**（23 条链里走完 12 条），月钟下补的锚点第一次真的被读到

## 5. 重标定（依据第 4 节）

- [x] **史评五档划线重标**：85/65/40/20 → **78/60/42/22**（前端 `HISTORY_RATINGS` +
      后端 `REPUTATION_BANDS` 两份同步，mirror-consistency 守卫）
      实测占比 9% / 30% / 25% / 16% / 20%；旧划线在年钟下会把五档压成两档（开链组 0/36/64/0/0）
- [x] **刻意不动 `TURN_YIELD.reputation = -3`**：实测降到 −2 会让分布整体上移约 63 点、
      全员撞 100 封顶 —— 衰减与增益是同一架天平两端，改时钟时只能重划刻度，不能单边改数值
- [x] **刻意不动产出 +50 / 养饷 K=4 / 兵员 +15**：它们是"每回合率量"，年钟没有改变单回合语义；
      要动必须成对动（历史上单独放大产出会让破产后果空转，#3 踩过）
- [x] **刻意不动事件 effects 量级**：原以为要按 1/1.65 压通胀，实测发现年钟 + 1912 结算后
      "太快撞线"这个前提本身消失了（游戏不再中途结束），压增益只会让 `time_up` 变多，
      不解决任何新问题 —— 留给"守成阶段缺目标"那条真正的问题
- [x] `balance-regression` 断言改写：`avgTurns ≤ 50`（防速通）→ `avgTurns ≥ 60` + `maxFinalYear > 1912`
      （防"走不完年代"），并加注释说明**胜率语义已变、不可与月钟直接比**
- [x] 文件头快照整段重写为年钟数字，月钟数据下移为「月钟历史」保留（含被否掉的三个方向）
- [x] 意外收获记录在案：粮草下限 160 → **60**（关链）/ **0**（NPC 档），断粮惩罚第一次真的触发；
      #3 当时把"惩罚休眠"归因于内容侧缺口，**有一部分其实是时钟太短造成的**，归因已在文档里打折
